## 2. STEP 0 附带发现：git 引用写入异常（重要）

本机 `git commit` / `git update-ref` 对 `.git/refs/heads/**` 的 lock-rename 写入会静默丢失（返回 0 但 ref 文件不出现；objects 和 reflog 写入正常）。疑似安全软件/同步盘拦截。**已用 PowerShell 手动写入 `.git/refs/heads/feature/content-growth-loop = 5456baf…` 恢复**。

Codex 后续每次 commit 后必须验证：

```powershell
git log --oneline -1   # 若报 "does not have any commits yet"，说明 ref 又丢了
# 恢复：手动写 .git/refs/heads/<branch> 文件内容为 commit hash（hash 从 reflog .git/logs/HEAD 最后一行取）
```

## 3. STEP 2 原始审计：重复操作风险清单

> 以下保留原审计依据。第 1–3 项已完成并验证；第 4 项补充写入超时后先检查历史的提示，跨请求幂等键留在 Optimization Backlog。复盘按钮沿用接管时已有的 `disabled={busy}`，未重写。

已有保护（验证过代码，不要重复做）：

- 前端 `GrowthLoopPage.act()` 全局 `busy` 守卫：busy 时直接 return，覆盖所有走 act() 的按钮（保存/分析/生成/审核/发布/流量/Analyze/实验结论/加载 demo）。
- 服务端幂等：`analyze`（有 analysis 直接返回）、`generate`（status!==draft 直接返回）、`contents/:id/analyze`（按 metricsId 缓存 feedback）、`reject`（已 rejected 直接返回）、`decideExperiment`（EXPERIMENT_COMPLETED 409）、demo 加载（`seeding` 标志 429 + seed 去重）。
- 乐观锁：所有写操作带 `revision`，陈旧提交 409 STALE_REVISION。

**待修复问题（按优先级）**：

1. **`apiRequest` 无超时**（`apps/web/src/lib/api.ts`）：mutation 请求若 API 挂起，`busy` 永远为 true，页面卡在"处理中，请勿重复提交…"，只能刷新。→ 给 fetch 加 AbortController 超时（如 30s），超时后走 error 分支释放 busy。useRemote 已有 AbortController，但 apiRequest 本体没有超时。
2. **`保存复盘` 按钮无 disabled**（`GrowthLoopPage.tsx` RetrospectiveEditor，line ~179）：act() 守卫兜住了重复提交，但按钮无 loading/disabled 反馈。→ 加 `disabled={busy}`。
3. **`保存流量` 非幂等（by design 但每次点击一条新记录）**（`MetricsEditor`，service.recordMetrics）：busy 守卫已挡住连点；误双击产生两条相同 metrics 的风险低但存在。可考虑：短时间内完全相同 payload 服务端去重，或前端提交后禁用直到 refresh。最小修复即可，别过度设计。
4. **`创建内容` 无幂等键**（service.createContent）：连点被 busy + 成功后 createdId 成功页兜住；API 超时重试会产生两条 draft。低优先级，可在前端提交后立即禁用（已有 busy）并在失败时提示检查历史。
5. `exportPng` 用自己的 `exporting` state，不走 busy，无问题但注意别和 act() 混用。
