# V1.3 local persistence, migration and recovery

Default server storage is `CONTENT_REPOSITORY=sqlite`, `SQLITE_PATH=data/emotion-studio.sqlite`. Relative paths resolve from project root, including npm API workspace startup. Requires Node 24. Stores sources, analysis, generation history, publication records, performance, retrospectives, saved edits, review states, original AI drafts, metrics, feedback and strategies. API and MCP share the same configured file. Explicit memory and PostgreSQL database modes remain available; exited memory cannot be recovered.

SQLite uses foreign keys, WAL, FULL synchronous writes and a five-second busy timeout. Checked-in `packages/database/sqlite-migrations/0001_local_persistence.sql` runs transactionally on open. Normalized checksums protect historical migrations; unknown future versions and failed upgrades are rejected. Revision and source guards share the write transaction.

Run from project root with NEW output filenames:

```powershell
npm run persistence -- status
npm run persistence -- backup --out data/backups/studio-2026-10-09.sqlite
npm run persistence -- export --out data/backups/studio-2026-10-09.json
npm run persistence -- restore --input data/backups/studio-2026-10-09.sqlite --out data/restored-studio.sqlite
```

Backup/restore include committed WAL pages using online backup, reserve new targets exclusively, and verify integrity. Restore opens the source read-only and rejects empty/unrecognized databases. Do not copy just the main file of a running SQLite database. Roll back by stopping the API, preserving the current file, and selecting the separately restored file through SQLITE_PATH. Do not run old code against a newer schema.

Capture a RUNNING memory API while idle, then import additively:

```powershell
npm run persistence -- capture-memory --url http://127.0.0.1:8787 --out data/backups/live-memory.json
npm run persistence -- import --database data/migrated-studio.sqlite --input data/backups/live-memory.json
```

Memory capture requires two identical reads; a stopped/changing API fails without an output. SQLite export reads all tables in one transaction. PostgreSQL export uses two matching reads; pause writes and configure existing server-only DATABASE_URL and CONTENT_REPOSITORY=database. Snapshots use strict DTOs and SHA-256 content checksums. Imports retain IDs/revisions, reject conflicting IDs/content/strategies or broken sources, and roll back completely. Re-import is idempotent. Import into an existing file creates a new backup first.

English keeps existing `data/english-topic-history.json`, `data/english-drafts/` and `output/` storage and five-page renderer. A COMPLETE backup includes the SQLite backup, English files/output, and the AI usage JSONL ledger when present. Stop English edits/exports during file copying. ENGLISH_ROOT can isolate its files under another local root; default is project root. Databases, private drafts, backups, ledger, output and secrets remain ignored by Git.
