# V1.3 小红书内容工作台

本地 Web 打开 `/xiaohongshu`，或从左侧导航选择“小红书工作台”。页面连接同一 Growth Loop 数据仓储；SQLite 模式下，复盘、生成历史、编辑内容和审核状态随 API 重启保留。所有生成内容先进入“待审核”，批量生成不会自动通过审核，也不会登录或发布到小红书。

## 日常使用

1. 选择“个人成长”或“情绪灵感库”账号及内容形式。个人成长需要先到“复盘记录”保存并分析真实经历，内容潜力达到 6 分后，才会出现在“真实复盘来源”选项中。
2. 在主题列表逐行输入主题，每批 1–10 个，每个最多 120 字。点击“批量生成”，页面逐条显示进度和成功、重复、失败结果，处理期间禁止重复提交或改动这批输入。
3. 重复项会复用历史稿件并提供打开链接。失败项如已创建草稿会保留该草稿；点击“重试失败项”只重新处理失败主题，服务端先检查是否已经完成，避免连接超时后盲目创建第二份。
4. 打开每篇稿件的审核页，核对事实、正文和标签，保存修改并明确“通过审核”。批量工作台不替代逐篇人工审核。已发布记录使用已有只读快照。
5. 在生成历史中按账号、审核状态或主题筛选，勾选需要的稿件。“选择当前列表”最多选择前 50 篇；可以清空或逐篇调整选择。只要所选内容中有一篇尚未通过审核，批量复制和导出保持禁用。
6. 全部通过审核后，可“复制所选发布文案”、导出 TXT 或 JSON。导出使用当前保存版本；若稿件被其他窗口更新，服务端拒绝旧版本请求，点击“刷新历史”重新读取后再选择。单篇“复制正文与标签”可复制当前保存稿件供编辑；剪贴板不可用时，页面提供可手动选择的文案框。

页面保留“English 50句 · 五页图片工作流”入口，跳转既有 `/english`。50 句、每页 10 句及五页图片生成继续使用原工作流；小红书批量主题表单只处理成长与情绪账号。

## 去重与导出规则

主题去重同时考虑账号、内容形式、真实复盘来源及主题。主题规范化全角字符、首尾/连续空白和英文大小写。因此同一账号与来源下的 `ＦＯＣＵＳ  today` 和 `focus today` 被视为重复；不同账号、复盘或形式保持独立。这是精确主题去重，不是语义相似性判定，人工仍需检查正文是否重复。

失败留下的 `draft` 可以继续生成；已经进入审核、通过、发布或拒绝的同一主题会返回现有稿件。需要新的创作方向时，应更改主题、来源或形式。合成 Demo 历史不参与真实工作台列表与主题去重。

同一 API 批次中的重复失败输入保留失败状态及原错误，不再次调用生成，也不会声称不存在的稿件已被复用。前端“重试失败项”发起新的请求，重新检查已保存状态后继续。

批量发布文案导出只允许 `ready` 或 `published` 状态，并逐篇核对 revision。TXT 包含标题及纯文本发布文案；JSON 另保留 ID、revision、账号、状态、实际 Provider 和完整 writing/english 内容。单个选择列表最多 50 篇，重复 ID 或旧 revision 被拒绝。复制/导出本身不保存未审核修改，也不改变审核状态。

## 开发接口与验证

公共 DTO 位于 `packages/contracts/src/xiaohongshu.ts`：

- `POST /api/v1/growth-loop/batch/generate`：接收 `items`，最多 10 条；逐条返回 `generated`、`duplicate` 或 `failed`，单条失败不阻断其余主题。同一 API 进程已有批量任务时返回 `BATCH_BUSY`。
- `POST /api/v1/growth-loop/batch/export`：接收 `{ items: [{ id, revision }], format: "text" | "json" }`，返回文件名、MIME type、文本及总篇数。

Web 为及时显示进度，逐条调用同一批量接口。刷新后可以从持久化历史继续审核或重试；它不实现跨进程任务队列。

目标测试命令（从各 workspace 目录执行，限制单 worker 以减轻本机资源压力）：

```powershell

node ../../node_modules/vitest/vitest.mjs run src/xiaohongshu.test.ts --maxWorkers=1 --minWorkers=1 --no-file-parallelism
# apps/api
node ../../node_modules/vitest/vitest.mjs run src/growth-loop/batch-routes.test.ts --maxWorkers=1 --minWorkers=1 --no-file-parallelism
# apps/web
node ../../node_modules/vitest/vitest.mjs run src/pages/XiaohongshuWorkbench.test.tsx --maxWorkers=1 --minWorkers=1 --no-file-parallelism
```
