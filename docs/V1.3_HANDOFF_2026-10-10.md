## 实现和兼容性

- **SQLite 默认持久化**：素材、分析、生成历史、复盘、保存的人工编辑、AI 原稿、审核状态、发布快照、指标、反馈和策略记忆保留。API 和 MCP 读取同一配置文件。使用事务、WAL、外键、乐观 revision 与带校验和的迁移；显式 `memory` 与 PostgreSQL `database` 模式仍可选。English 延续原有 JSON 历史/草稿和 PNG 文件格式。[存储、迁移与恢复说明](V1.3_STORAGE.md)。
- **Provider 适配层**：支持 Mock、DeepSeek 和 OpenAI-compatible Chat Completions。收费门独立于 Provider/key 配置，默认关闭；每次调用设定超时，最多三次尝试，对可重试失败退避，严格验证输出。符合条件的失败返回准确标记的 Mock/Demo；鉴权、禁用、取消及账本失败保持错误。持久化 JSONL 调用账本记录可用 token、估算成本及错误，不含 prompt、输出或密钥；价格/usage 未知时成本为 null。[配置及真实验收边界](V1.3_PROVIDERS.md)。
- **小红书工作台**：每批 1–10 主题，按账号/形式/复盘来源及规范化主题去重；进度、部分失败与失败项重试；历史搜索/审核状态筛选；人工保存与明确审核；最多 50 篇已通过稿件的复制、TXT/JSON 导出，旧 revision 拒绝导出。批量生成不自动批准。个人成长要求已分析且潜力至少 6 分的复盘来源。[操作、API 与去重规则](V1.3_WORKBENCH.md)。
- **English**：保留 50 句、每页 10 句、五页 900×1200 PNG，以及 Markdown/JSON 发布包。未保存编辑可实时预览及单页导出，整包仍要求人工批准。实测发现快速编辑后 iframe 空白，已修复并通过完整浏览器流程及原有 smoke 复验。

## 本地启动和使用

Windows 使用 Node.js 24（本次为 24.15.0）与 npm；PNG 渲染使用已安装的 Microsoft Edge。项目根目录执行：

```powershell
Set-Location -LiteralPath 'C:\Users\lin\Documents\ChatGPT\情绪灵感库\emotion-content-studio'
npm ci
npm run dev
```

Web：[小红书工作台](http://127.0.0.1:5173/xiaohongshu)、[English 工作流](http://127.0.0.1:5173/english)；API：`http://127.0.0.1:8787`。默认 SQLite 位于 `data/emotion-studio.sqlite`，AI 为 Mock、English 为 Demo、收费门关闭，不需要模型密钥。启动 shell 的已有环境变量会影响配置；根 `.env` 不会被该命令自动加载。

小红书：输入主题 → 批量生成 → 打开单篇核对/保存 → 明确通过审核 → 返回历史勾选 → 复制或导出。个人成长先保存并分析复盘，再选择合格来源。English Demo 可使用“尴尬时刻英语50句”：生成 → 修改逐句英文/中文 → 1–5 页核对 → 当前页导出，批准后可生成五页整包。

仅需临时旧行为时，在当前 shell 显式设置 `$env:CONTENT_REPOSITORY='memory'`，停止前先捕获；该模式重启会丢失内存数据。清除该变量回到默认 SQLite。后续真实 AI 接入应先阅读 Provider 文档，由用户另行授权并配置服务器密钥和收费门；本次交接不启用它。

复验：

```powershell
npm run check
npm run test:e2e:restart
# 另一个终端先启动 Web，保持其运行，再执行：
npm run test:e2e:workbench
node --import tsx apps/api/src/english/preview-smoke.ts
```

`check` 构建编译 API 后，重启 E2E 可直接运行；两种 E2E 都使用自己的新 SQLite/English 目录和 API，不停止用户服务。完整工作台 E2E 需要 Web 开发服务器。每次创建新证据目录，保留历史。

## 备份、迁移和恢复

从项目根目录使用全新目标文件名；备份与恢复不会覆盖已有文件：

```powershell
npm run persistence -- status
npm run persistence -- backup --out data/backups/studio-2026-10-10.sqlite
npm run persistence -- export --out data/backups/studio-2026-10-10.json
npm run persistence -- import --database data/migrated-studio.sqlite --input data/backups/studio-2026-10-10.json
npm run persistence -- restore --input data/backups/studio-2026-10-10.sqlite --out data/restored-studio.sqlite
```

确认恢复文件后，停止当前 API，保留当前数据库，在启动 shell 设置 `$env:SQLITE_PATH='data/restored-studio.sqlite'` 后重新启动。不要只复制运行中数据库的主文件；在线备份包含 WAL。完整备份另需 English 的 `data/english-topic-history.json`、`data/english-drafts/`、`output/` 与 `data/ai-usage.jsonl`，复制这些文件前暂停 English 编辑/导出。迁移导入保留 ID/revision，重复导入幂等，冲突整批回滚。详见存储文档。
