## PostgreSQL 复测命令

在项目根目录打开 PowerShell，由用户或受授权的测试环境提供专用测试库连接串；不要把包含密码的连接串写入 Git、交接文档或测试日志。

```powershell
Set-Location -LiteralPath 'C:\Users\lin\Documents\ChatGPT\情绪灵感库\emotion-content-studio'
$env:TEST_DATABASE_URL = '<专用 PostgreSQL 测试库连接串>'
$env:AI_PROVIDER = 'mock'
$env:ENGLISH_AI_MODE = 'demo'
npm run test -w @emotion-studio/api -- src/content/repository.contract.test.ts src/content/persistence.integration.test.ts src/growth-loop/repository.test.ts
npm run test -w @emotion-studio/database -- src/migrations.test.ts
npm run check
```

前三个 API 文件有 **27 项**：13 项 memory + 14 项 PostgreSQL；database 迁移文件有 **2 项**。完成复测应确认原来的 **16 项 PostgreSQL 条件测试全部执行**，而不是只看命令退出 0 或套件中 memory 测试通过。启用条件后数据库连接/权限失败应作为失败报告，不能再以环境缺失解释为已验收。

关闭该 PowerShell 的测试库配置时可执行：

```powershell
Remove-Item Env:TEST_DATABASE_URL
```

## 本地 SQLite 真实重启 E2E

```powershell
npm run build
npx tsx scripts/v1.3-restart-e2e.ts
```

脚本使用新的临时目录、SQLite 文件、合成输入、显式 mock AI 和 English demo，启动编译后的 `apps/api/dist/server.js` 子进程。它创建复盘、分析、生成草稿、保存编辑、人工审核及本地发布记录，保存指标/反馈，以及待审核、已通过、已拒绝记录和 Studio 生成历史；停止自己的 API 子进程后，以同一 SQLite 文件启动新的进程，逐字段比较状态，并复测 stale revision 错误封装与反馈缓存。

每次证据保留在 `.tmp-check/v1.3-restart-e2e/run-*`：`before-restart.json`、`after-restart.json`、`api-1.log`、`api-2.log`、`result.json` 和测试 SQLite 文件。可用 `RESTART_EVIDENCE_DIR` 指定证据父目录。测试只停止它创建的子进程，不连接运行中的用户 API，不调用付费模型，不记录外部平台发布验收。

当前 PostgreSQL 验收限制：如果没有专用 `TEST_DATABASE_URL`，原 16 项继续 skipped，最终交接必须明确这一阻塞及上述复测条件。迁移断言修复不等于 PostgreSQL 实际运行通过。
